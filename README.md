# unMotion beta update feed

This branch serves **unMotion 0.5.0-beta9** (Plugins-tab version **2026.11.11.01-0.5.0-beta9**). Requires Unraid 7.3.2 or later. The [stable feed](https://raw.githubusercontent.com/rtho782/unmotion/plugin-stable/unmotion.plg) and Community Apps installer remain on 0.4.9.

Opt into beta updates with the [beta installer](https://raw.githubusercontent.com/rtho782/unmotion/plugin-beta/unmotion.plg) through **Plugins → Install Plugin**. Existing beta installations use **Plugins → Check for Updates → Update**. The small descriptor downloads a separate SHA-256-verified TXZ and retains the current package for offline boots. Stable installations are not switched automatically.

Beta9 supports experimental live migration of running BIOS or supported UEFI guests with one to sixteen independent raw/qcow2 file disks or whole raw ZFS volumes, including mixed guests, optional software TPM 2.0 and ordinary bridge NICs. Both peers need matching Beta9, an active compatible custom CPU and the qualified matching virtualization stack (libvirt 12.2.0). TPM requires fresh matching swtpm/libtpms implementations; state moves natively into independent job/UUID-scoped storage, without shared storage. Empty read-only file CD-ROM drives may remain, but attached ISOs, native ZFS-encrypted volumes, unrelated block devices, passthrough and recovery/replication-managed guests remain excluded. Only one live job may run per host.

Zvols remain zvols in the configured destination parent, with full reservations; files remain sparse in the direct-pool image directory. Capacity checks combine requirements sharing a pool, include allocation overhead and 20% free-space headroom, and preserve destination dedup policy. Disk-copy and RAM-convergence observations are shown separately, not as an overall percentage or ETA. Source and partial copies retain space; no automatic reclamation is introduced.

The readiness dialog explains independent blockers and enables Start only after fresh full checks; submission checks again. Beta9 qualification covers mixed Unraid 7.3.4/7.4.0, actual source/destination loss during copying and handover, paired reconciliation, cleanup interruption/reboot/retry, ZFS renumbering and Linux TPM cold-boot/live integrity. Windows Server 2025 Core/active BitLocker and mixed-zvol coverage is inherited from earlier qualification, not freshly rerun. Read the bounded scope rather than assuming every Windows, TPM+PIN, Secure Boot, hardware or failure configuration is covered. Keep guest recovery material and backups available.

On the non-owning host, use **Clean up retained copy** on a settled live job to review exact inactive disks and state paths, then explicitly confirm deletion. Both paired Beta9 hosts must remain reachable and prove current ownership. Short owner leases, immutable identity plans and per-object intents/receipts protect current data; native start fences and job history remain. Use **Review/retry cleanup** after correcting a blocker or restarting a host; deletion never resumes automatically. New ZFS files bind dataset GUID/inode identity across import-order renumbering; unproven legacy files/NVRAM/TPM remain protected. Current-owner, ordinary hand-back and recovery authority are not cleanup targets.

An uncommitted receiver requires successful native-finish proof tied to its exact boot, QEMU lifetime and storage/XML contract before ownership/resume. Paused state or received-byte counters are not completion proof. Reconciliation rejects a previous-boot receipt rather than starting a replacement or incomplete receiver. There is no automatic failover.

Cached CPU comparison, shared-mode suggestions, reviewed XML application and a pinned default for new Unraid VMs remain available. CPU changes take effect after a full stop/start, not a guest reboot. Intel nested live moves require nesting and full CPU validation on both hosts; AMD nested live moves remain blocked. Cached observations never authorize migration.

After a settled live move, fully stop its owner and choose **Return to ordinary workflows**. Paired checks enable otherwise-supported Cold/Warm Move, clone, CPU edits and replication-only configuration, preserving non-owner fences. TPM guests still cannot be cloned. Recovery arming after hand-back remains unsupported. Retained source/partial disks, NVRAM and TPM state are not automatically reclaimed.

Scheduled replication supports explicit retirement with keep/delete choices, paired cleanup receipts and independent new cycles for the same VM/destination. Prepared-copy removal preserves source bases until destination acknowledgement. Displayed point counts follow authenticated inventory/pruning replies. Encoded zvol ordinary transfers require the separate optional encoded-path capability on both hosts; ambiguous names are rejected.

Wire protocol **7** remains unchanged; live capability is **4**, retained-copy cleanup capability **1**, encoded-zvol capability **1**, and guarded ordinary/retirement capabilities retain their existing gates. Finish active operations/cleanup workers, pause replication, reconcile live jobs and stop live/recovery-managed guests before updating. Unresolved ownership or pending hand-back blocks normal upgrades/removal; unfinished cleanup also blocks uninstall. Keep the installed descriptor named `unmotion.plg`; never delete ownership records to bypass safety checks.

The descriptor is byte-identical to the versioned release asset.
