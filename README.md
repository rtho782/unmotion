# unMotion beta update feed

This opt-in feed offers **unMotion 0.5.2-beta5** (Plugins version **2026.11.14.01-0.5.2-beta5**), requiring Unraid 7.3.2 or later. Stable and Community Apps remain on **0.5.0**. This descriptor retains the **plugin-beta** update URL.

Install via [unmotion.plg](https://raw.githubusercontent.com/rtho782/unmotion/plugin-beta/unmotion.plg), or use **Plugins → Check for Updates → Update** on an existing installation. Keep its installed name **unmotion.plg**. The small PLG downloads a separate versioned TXZ and retains the verified current package for offline boots.

The beta adds native OpenSSH/libvirt live handover without the custom Go payload forwarder, RPC inspector or extra application-controlled pause. Both matching beta peers must explicitly enable **Native live migration trust** in Settings: temporary system-libvirt/forwarding access is administrator-equivalent, not a per-VM sandbox. Permanent pairing keys, strict host pins, persistent start fences and authenticated ownership reconciliation remain. A same-vendor older-generation destination is allowed only after fresh validation of the complete active guest CPU.

**SSH encryption** selects AES-128-GCM (default) or AES-256-GCM for outgoing live, Cold/Warm Move and replication connections. Live jobs pin their cipher; ordinary workers capture it at launch. No silent fallback or plaintext option is offered. Performance depends on the hosts and path. The 30-minute transfer limit and capacity/headroom requirements remain; neither wire speed nor subsecond handover is guaranteed.

Before updating, pause replication and finish/reconcile jobs and cleanup. A settled live-migration owner can remain running when the beta5 target installer verifies identical native fencing code, current libvirt proof and its existing exact QEMU admission. No process is adopted or ownership/admission rewritten; retained old copies stay fenced. Incompatible fencing changes, missing/inconsistent admission, pending hand-back and unfinished live work still block this exception. Active recovery-managed guests still require shutdown, and uninstall rules are unchanged. The Plugins console prints the actual refusal reason. Preserve settings, pairings and authority records; never bypass upgrade/start guards. Update both peers to matching **0.5.2-beta5** before live migration and enable native trust on each. Old queued guarded jobs are not converted; resolve them and create a fresh native job. Wire protocol 7/live ABI4/native-data1 remain, with additional native capability 1. Ordinary supported operations retain their own capability gates.

The feed is byte-identical to the released, lab-qualified beta PLG and references its exact tested TXZ/hash. Beta4-to-beta5 upgrades kept migrated Linux file/zvol and Windows TPM/BitLocker owners running, with original QEMU and guest continuity. Native starts of all three retained source copies were rejected before QEMU both before and after upgrading. Incompatible-fence installer refusal, mixed-version preflight refusal, a native file round trip and a protected Windows cold boot passed on DEV01 7.3.4 / DEV02 7.4.0. The unchanged native engine inherits beta4's cached reboot and bounded host-loss qualification; those fault/performance tests were not repeated for beta5. Ambiguous outcomes can remain fenced for operator review; no automatic failover is provided. Passthrough, attached ISOs, AMD nested live migration and other unsupported layouts remain blocked.
